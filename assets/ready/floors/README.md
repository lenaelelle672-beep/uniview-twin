## World frame (the same frame as the running scene)
- Units are metres. **x = east, z = south (+z is south, −z is north), y = up.** This is the three.js frame used by
  `src/scene/scale.ts` (`pageToWorld`).
- Origin: the centre of the site.pdf 22F tower survey rectangle, at site page pt (1620.077, 762.686). site.pdf scale is 8.306 pt/m.
- Every x/z pair is `[x, z]`. `meta.elevation_m` is the floor level from the scene formula `6 + (n−2)·4.2` (F1 = 0).
  The level printed on the drawing is in `meta.levelFromDrawing` (1F–8F; null on 12F–21F, see section 标高).
- Transform from PDF page points (y down) to world: `x = px/pt_per_m + tx`, `z = py/pt_per_m + tz`, with rotation 0.
  12.pdf has page /Rotate 270. It is first converted to the displayed north-up frame (`X = uy, Y = 842 − ux`).

## Top-level keys
| key | type | meaning |
|---|---|---|
| `meta` | object | provenance and QA, see below |
| `outlineType` | string | (F12 only) what the outline line is. F12 uses the slab edge (板边线), not the facade envelope |
| `outline` | `[[ [x,z], ... ]]` | outer outline ring(s), not closed (first ≠ last). F13 = outer fin envelope incl. the curved south facade |
| `cores` | `[{id, name, polygon:[[x,z]...], pagePt:[x0,y0,x1,y1]}]` | core rectangles (coreW, coreE) |
| `coreWalls` | `[{rect:[x0,z0,x1,z1], pagePt}]` | (F13) filled core wall rectangles |
| `columns` | `[{id, center:[x,z], w, d, shape, pagePt}]` | w = size along x, d = size along z (m). `shape` is `rect` or `round` (round: w = d = diameter) |
| `rooms` | `[{name, labelArea_m2, label:[x,z], polygon, polygonArea_m2, confidence, note, method}]` | `name` is the PDF text. `labelArea_m2` is the printed area (null if none). `polygon` is an axis-aligned rectangle found by ray-casting from the label to the nearest wall/glass/door line, or null |
| `walls` | `[{kind, a:[x,z], b:[x,z]}]` | partition/wall line segments (kind: wall, glass, …) |
| `desks` | `[{id, n, row, center, size:[sx,sz], facing:[fx,fz], rotY, colEdgeDist_m, nearestColumn, pagePt, ...}]` | workstations, see below |
| `officeDesks` | `[{center, size}]` | private-office tables (not counted as workstations) |

### Desks
- `center` is the desk-top centre. `size` is the extent along [x, z] in metres.
- `facing` is the unit vector the seated user looks along. It points from the chair side to the desk/monitor side, in world x/z.
- `rotY = atan2(−fx, −fz)` rad, the three.js Y rotation for a desk model whose front (monitor side) is local −Z,
  matching the current scene desk model.
- `id` = `Fxx-n`. `n` is 1-based and ordered row-major from the NW: rows are grouped by z (north to south), then sorted by x (west to east).
  `row` is the row index.
- `colEdgeDist_m` = distance from the desk centre to the nearest column edge (rectangle or circle). `nearestColumn` = the column id.
- Desks are exactly as drawn. They are never moved to satisfy D046/D060. Violations are listed in `meta.deskRule.list`.

### Rooms: `confidence`
- `high`: the rectangle is closed on 4 sides and its area is within about 15% of the printed label area.
- `medium`: closed rectangle, but no label area or a larger difference. Or the room is not rectangular and the rectangle is an approximation.
- `low`: rays escaped or the rectangle contains other labels. `polygon` may still be given but is unreliable.
- `none`: no polygon (`polygon: null`). Only the label position and name are kept.

## `meta`
- `floor`, `elevation_m`, `generated` (ISO time, +08:00)
- `source`: `{file, sha256_8 (first 8 hex of sha256), page, title, printedScale, pageRotation?}`
- `extraction`: vector (PyMuPDF `get_drawings()` with OCG layer names). No raster tracing was used for F12/F13.
- `scale`: `{method, pagePt, pt_per_m, chainCheck[...]}` gives the dimension line used and a check of each segment.
- `transform`: `{formula, rotation_deg, pt_per_m, tx, tz, fit}`
- `registration`: per-corner residuals (`fitCorners` / `checkPoints` for F13 against the site.pdf layer
  `ROOF-OVLK$0$C-BLDG-OTLN`; `columnResiduals` / `cornerColumns` for F12 against the F13 columns), plus RMS/max values and notes.
- `counts`, `deskRule` `{rule, minCentreToColumnEdge_m, minDesk, violations, list}`, `sceneTowerBox`, `knownIssues[]`.

- `walkable`: the outline minus the obstacles, eroded 0.4 m, simplified 0.05 m, on a 0.01 m grid, with crumbs under 0.5 m² dropped. Obstacles:
  - cores and `coreWalls`
  - rooms with a polygon
  - desk and officeDesk boxes
  - columns
  - walls (centre-lines buffered 0.1 m)
  - F03's SE box x 63–95, z 70–108 (D098)
  - **the excluded room cells (D100 B)**

  **Cell method (also in the `.walkable.json` → `walkMeta.rules.cells`):** D100 room cells: all `walls` segments (every kind: wall, glass, core-wall, shaft/stair/toilet partitions, wall-finish) as centre-lines, buffered 0.9 m (square caps, mitre joins; no extra snapping — the 0.9 m buffer itself closes gaps ≤ 1.8 m), unioned with the core polygons; cells = outline − that union; each cell is grown back by 0.9 m (clipped to the outline) so it reaches the wall centre-lines. A grown cell is excluded from walkable if any room label (rooms[].label, with or without polygon) inside it matches 机房/设备/空调/新风/网络/配电/弱电/水泵 and the cell is ≤ 300 m² (bigger cells are open halls where the wall data does not close the plant room: kept, counted as plantOpenKept — approved D102; inside them a 5 m disc around every plant-keyword label point is removed from walkable, D102), except that a cell with a label containing 设备区 is always excluded (D102, keyword rule, currently only F08 设备区 315 m²), or if it contains no room label at all and the split cell (before growing back) is < 50 m² (the grown cell is what gets excluded).
  Rooms with only a label point are otherwise not subtracted.
- `walkPaths`: up to 12 closed, simple polylines. Every segment is covered by `walkable` (so it keeps ≥0.4 m from obstacles and wall faces). Other rules:
  - ≥1.5 m from every label-only room label, ≥4 m from 上空 labels, and no loop encloses a void label
  - 15–300 m long; outer rings must have an enclosed mean width ≥2 m
  - distinct from each other (Hausdorff > 2 m)

  **D100 changes:**
  - **A (connectivity):** a component counts as connected if it touches any core, stair or elevator.
  - **Two components (F04–F08):** the east block and the tower half each get paths, split in proportion to area, at least 2 each
    (`walkMeta.components[].pathIndex`).
  - **C1 (east block zones):** the east block takes the best loop in the north, middle and south thirds first.
  - **C2 (tower loops):** tower half-floor loops are inset 1.5–3.5 m and opened by 1 m (round joins) to remove the zig-zag around columns.
  - **C3 (simplification):** every path is simplified with Douglas–Peucker 0.1 m on 0.01 m-rounded rings. A simplified segment that
    is not covered by `walkable` gets its original points back.
- **D102:**
  - **5 m disc:** in every kept open-hall cell (`plantOpenKept`: > 300 m² with a plant-keyword label) a 5 m disc around each
    plant-keyword label point is subtracted from `walkable`, so paths stay ≥5 m from those labels (`.walkable.json` → `walkMeta.rules.plantLabelBuffer = 5`;
    the points are listed in `plantOpenKept[].plantLabelPoints`).
  - **设备区:** any cell with a label containing 设备区 is excluded whatever its size. This is a keyword rule; today it applies only
    to F08 设备区 (315 m²) (`walkMeta.rules.forceExclude`).

  voidClear_m, maxPaths}}`.
