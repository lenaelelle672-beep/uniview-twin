## 做什么

DEMO（`?demoEdit=1` 或作者态 `debugHelpers`）或密模层（`?style=model`）时，用已钉的 drei `CycleRaycast` 轮询密叠命中。`onChanged` 只写侧栏的 `focusedDeskId` / `focusedDeviceId`。默认键是 Tab（`keyCode` 9）。`scroll` 固定 false，滚轮仍交给 `CameraControls`。

观众地址默认关，不请求 `CycleRaycast.js`。`?cycle=1` 强制开，`?cycle=0` 强制关，本页「轮询」按钮再盖过地址。补 T052 框选、T055 Bvh、T078 meshBounds 的点选歧义，不替换它们。

同一 `InstancedMesh` 的嵌套子节点按 `instanceId` 分开。工位桌、椅用实例序号加一写成工位号；显示器再写成该工位的 `-PC`。对象自己带的 `deskId` / `deviceId` 优先。框选代理和拖摆手柄不写侧栏。drei 只用 `object.uuid` 判断命中列表有没有变，同一网格换实例不会重置 cycle；侧栏身份把实例序号算进去。

Shift+Tab 让给框选，不轮询。拖摆进行或 Shift 左键框选时卸下 filter。指针按下时不吃 Tab，避免 `onPointerCancel` 打断镜头。输入框、按钮和侧栏控件里的 Tab 在捕获阶段拦住。指针不在画布上时 Tab 仍走页面焦点。

生产构建在算 dock 哈希之前摘掉接线，哈希定稿后再把 `CycleMount.js` 接到 dock。`CycleRaycast` 本体在 `CycleRaycast.js`，只有开关打开才请求。drei 仍是 10.7.9，没有新的 npm 依赖。雾密度、`USER_CAMERA_SMOOTH_TIME`、balancedFx 都没有改。没有改 `boxSelect.ts`、`CameraRig.tsx`。

锁机 cutoff 会跟到第一笔 prefetch（`floorDecor`）的 `responseEnd`。总览上 `startFloorShellNow` 先只拉 `floorDecor`，等这条 `import()` 完成再发 dock、标签、楼层镜头、textRuntime。DemandLoop 和软阴影再等 `__twinFirstPrefetchDone`。楼层路径仍立刻放行。

## 已知差距

- 滚轮不轮询。drei 默认会在 document 上 `preventDefault` 滚轮，那会和镜头推拉叠在一起，所以 `scroll` 关掉，只留 Tab。
- 侧栏用现有的 `focusedDeskId`。人已经在该层时，原有的楼层镜头会跟着这个工位取景。这里不调用 `focusDevice`，也不增加 `focusSeq`。
- 「关」只记在本次页面。刷新之后 DEMO 或模型层会再打开。
- 按钮是独立的一小块，跟「拖摆」一样，没有塞进 React 渲染的图层列表。
- `cameraRest` / `frameSchedule` 跟着 `floorDecor` 的静态 import 在解析后立刻发出，只比 cutoff 晚约 1ms。没有再把它们改成动态 import。
