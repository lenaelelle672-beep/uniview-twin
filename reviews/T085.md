## 做了什么

书签条上多了一颗「常亮」按钮。默认关。点一下才向浏览器申请 `navigator.wakeLock.request('screen')`，这一下就是用户手势。再点一次 `release()`，屏幕可以重新休眠。

- `?wakeLock=1` 打开。演示模式 `?demo=1` 或 `?demoEdit=1` 也打开，挂上晚加载分包时就申请。
- `?wakeLock=0` 强制关，盖过演示模式。按钮禁用，标题写明地址栏带了这个参数。
- 地址栏同步会抹掉未知参数，所以开关同时读导航记录里的原始地址。
- 文档不是 `visible` 时不申请。藏到后台时先释放，避免没有可见文档还握着锁。回到可见且开关仍开着，再申请一次。
- `request` 或 `release` 抛错、拒绝、接口不存在、非安全上下文，都停在降级态，不抛进主路径。

按钮在持有时是「常亮开」，关掉是「常亮关」，开着但没锁住是「常亮」。

## 懒加载

生产构建里 `wakeLock.request` 只出现在 `assets/WakeLock.js`。

1. `dock.tsx` 里的接线在哈希定稿前被 `wakeLockAfterHash` 整段摘掉，所以 dock / index / balancedFx 的 vite 图不含这条 import。

`WakeLock.js` raw 5123，gzip9 2039。大于 hardGate 余量 42，所以必须留在 cutoff 外面。

## 浏览器

swiftshader，视口 1024 / 1366 / 1920，昼和夜。`__twinReady` 之后 `pageerror` 0，`console.error` 0。性能档总览同样 0。没有进入全屏。

- 默认 `?q=balanced`：按钮「常亮关」。点一下变成「常亮开」，`request('screen')` 一次，`held === true`。再点一次 `release()`，回到「常亮关」。
- 接着把文档拨到 hidden：阶段变成 `armed`，这次没有新的申请。拨回 visible 后又申请一次，重新 `held`。
- `?demo=1`：地址栏被收成 `/?q=balanced`。不用再点，按钮已经是「常亮开」，申请过一次。再点可以关掉。
- `?demo=1&wakeLock=0`：地址栏同样收成 `/?q=balanced`。按钮禁用，文案「常亮关」，标题说明 `?wakeLock=0`，申请次数是 0。
- `?wakeLock=1` 且 `request` 拒绝：按钮停在「常亮」，阶段 `degraded`，页面没有抛错。

## 复用

Screen Wake Lock 是浏览器 API，没有 npm 包，也不升 drei。接法沿用 T083 / T084 那条「dock 哈希定稿前摘掉、定稿后把独立分包接回去」。大屏常亮和全屏、画中画、桌面通知各管各的：全屏管画面尺寸，画中画管值守小窗，通知管标签藏到后台时弹一条，这里只管别让系统把屏幕睡掉。
