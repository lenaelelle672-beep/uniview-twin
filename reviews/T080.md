## 做什么

`?demoEdit=1` 或作者态（`debugHelpers`）时，用 drei `DragControls` 拖总览南侧的设备钉和家具落点。默认关，观众地址不请求 `DragControls.js`。补 T058 的轴柄和 T077 的浅拷，不替换它们。

六处落点：三枚设备钉（西打印机、东打印机、南相机）和三块家具垫。家具垫相对 T077 三盏浅拷偏到 +X（`[2.4, 0.33, 0]`），免得和灯体重叠抢射线。拖在水平面上，`axisLock` 为 `y`，高度锁在落点。家具浅拷跟着垫的水平位移走，浅拷的 y 留在 `0.12`。工位公式（D027）不改，也不去拖 InstancedMesh 桌。

拖的时候锁 `CameraControls` 轨道。按下时在捕获阶段记下 `enabled`，松手时只交还这一档。drei 在 `onDragEnd` 里会先把 `enabled` 写成 `true`，门闩在那之后改回来，所以原来已经关掉的镜头不会被拖摆打开。Shift 不开始拖摆，框选仍走 T052 自己的按下 / 松开。没有改 `boxSelect.ts`：改它会换掉楼层包文件名，那些名字写在入口里，hardGate 会多出几字节。

图层按钮「拖摆」可在本页关掉。关掉后场景里没有 `PlacementDrag`，`window.__twinDrag.on` 为 false。再点一次会挂回，这一页里拖过的位置还在。地址仍是 `demoEdit=1` 时，刷新会再打开，位置回到种子。

生产构建在算 dock 哈希之前摘掉接线，哈希定稿后再把 `DragMount.js` 接到 dock。DragControls 本体在 `DragControls.js`，只有开关打开才请求。`@use-gesture/react` 是 drei 的传递依赖，没有单独安装，也没有进 `package.json`。drei 仍是 10.7.9。没有 PivotControls。

`DragMount.js` 和 `DragControls.js` 各打进一份会话模块。会话状态放在 `globalThis.__twinDragState`，避免后加载的那份把 `window.__twinDrag` 写成关。

## 画面

生产预览 `http://127.0.0.1:5190`，Chrome swiftshader。`window.__twinReady === true`。1024、1366、1920，白天和夜间：`console.error` 0，`pageerror` 0。

- 默认总览：按钮「拖摆 / 关」，`window.__twinDrag` 为 `{ on: false, mounted: false, count: 0, axisLock: 'y', owner: 'camera-controls' }`。场景里没有 `PlacementDrag`。没有请求 `DragControls.js`。三宽、白天和夜间都是这样。
- `?demoEdit=1`：不点按钮就会挂上。`PlacementDrag` 下一组，3 个 `DragDevice`、3 个 `DragFurniture`。`window.__twinDrag` 为 `{ on: true, mounted: true, devices: 3, furniture: 3, count: 6, axisLock: 'y', moved: 0 }`。旁边有 T077 的 `FragmentClones`，3 个子节点。三宽、白天和夜间仍是 `mounted: true`、`count: 6`，控制台仍是 0。
- 把镜头对准西打印机钉后左键拖：拖的过程中 `dragging: true`、`latched: true`、`owner: 'drag'`，`controls.enabled` 为 false。松手后 `enabled` 回到 true，`owner` 回到 `camera-controls`。落点 y 仍是 0.45，x/z 变了，`moved` 为 1。
- 同一页再拖西侧家具垫：拖的过程中镜头同样锁住，松手交还。浅拷第一盏从 `(-8, 0.12, 28)` 跟着垫的水平位移走到新的 x/z，y 仍是 0.12。
- Shift 按住再拖家具垫：`dragging` 保持 false，落点和浅拷都不动，`controls.enabled` 保持 true。
- 点「关」之后 `PlacementDrag` 从场景里拿掉，`on: false`、`mounted: false`、`count: 0`。再点「开」会挂回 6 处，西打印机和西侧家具垫仍是刚才拖到的位置。

`npx tsc --noEmit` 通过（含在 `npm run build` 里）。`vitest run` 本单 4 条通过，框选 4 条通过，浅拷 5 条通过。全量 658 通过；`rectArea.test.ts` 有 1 条在基线 `86cdd32` 上就已经对不上（T071 之后的接线夹在面光和 `const LayerPanel` 之间），这次没有改那个断言。

## 已知差距

- 拖的是总览南侧的作者钉和垫，不是室内工位桌，也不是每台设备的徽章。工位仍走 `workstationPosition`。
- 「关」只记在本次页面。刷新之后 `?demoEdit=1` 会再打开，位置回到种子。
- 按钮是独立的一小块，跟「浅拷」「网格」一样，没有塞进 React 渲染的图层列表。
- 框选模块没有改。划界是：Shift 不启动拖摆，拖摆只锁自己按下前的 `CameraControls`。楼层里的框选单测仍通过。
