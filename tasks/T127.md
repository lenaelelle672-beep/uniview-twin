## 验收

- 进入单层房间后，只给这一层 `FloorInterior` 里的室内材质套 drei `useBoxProjectedEnv`（`@react-three/drei/core/useBoxProjectedEnv`）的 `onBeforeCompile`。默认开。`?boxProjectedEnv=0` 或 `window.__twinSetBoxProjectedEnv(false)` 关掉。
- 环境贴图继续用 `LocalEnvironment` 已经挂上的两张本地 HDR：`/hdr/kloofendal_48d_partly_cloudy_puresky_1k.hdr`、`/hdr/modern_buildings_night_1k.hdr`。不另拉文件，不用 drei `Environment`，不用 CDN。

- 幕墙、格栅、接缝、铝翅、檐口继续用各自的 `envMap` / `envMapIntensity`。本单不写这两项。`transmission > 0` 的材质不挂。不用 Reflector。
- 0 新 npm。不改 `package.json` / `package-lock.json`。不升 drei 10.7.9 / R3F 9.8.1 / three 0.186.1 / `@react-three/postprocessing` 3.1.3 / postprocessing 6.39.5。

## 改了什么

`src/box-projected-env/plan.ts` 做门闩和房间盒子。盒子的 XZ 用当前 `FloorSlab` 世界包围盒，Y 用这一层的标高和层高。`IndoorBoxEnv.tsx` 才深路径引用钩子。`mount.ts` 在人进入单层、并且 `__twinEnv.url` 是那两张本地 HDR 之一时，才 `import('./IndoorBoxEnv')`。

drei 10.7.9 的钩子仍按 `inverseTransformDirection` 打补丁，three 0.186 的物理环境光块已经改成 `transformNormalByInverseViewMatrix` / `transformDirectionByInverseViewMatrix`，替换会落空。钩子还会把 `worldpos_vertex` 换成不带 `instanceMatrix` 的写法。`bridge.ts` 在钩子的 `onBeforeCompile` 之后补上这两处调用，并把实例矩阵和 batching 加回去。不改 `node_modules`，不重写钩子。

生产构建走 `box-projected-env-after-hash`。哈希定稿前把 dock 里的接线摘掉。定稿后另出 `BoxEnvMount.js`、`IndoorBoxEnv.js`、`useBoxProjectedEnv.js`。react / fiber / `Vector3` 从已经哈希的入口包复用。物理环境光那一段 GLSL 只进钩子分包。

## 运行核对

均衡档总览双击 F12。`__twinBoxProjectedEnv` 为 on / mounted，`floorId` 是 F12，`hdr` 是白天那张本地 HDR，`useFrame` 为 false，挂上 6 个室内材质。抽样材质的编译结果带 `BOX_PROJECTED_ENV_MAP`、各一次 `parallaxCorrectNormal`，以及 `instanceMatrix` / `USE_BATCHING`。幕墙一侧五份材质没有 `boxProjectedEnv` 标记，缓存键仍是 `twin-curtain-v2` / `twin-grille-v1`。点「返回总览」后门闩回到 off-view，场景里不再有该标记。控制台没有 pageerror。

## 已知问题

- 钩子替换掉整段 `worldpos_vertex`。补丁只把实例矩阵和 batching 加回去，不恢复 include 里其余的阴影坐标。室内工位是实例网格，盒子和世界位置按实例矩阵算。
- 房间盒子不跟家具、工位爆炸走。楼层爆炸时门闩直接卸掉。
- 200ms 轮询复查门闩和楼板，没有 `useFrame`。状态没变时不 `invalidate`。
- 与本单无关的既有失败：`explodeFitGate.test.ts` 不允许 `FloorStageCamera` 出现 `frameloop`；`rectArea.test.ts`、`fileSave.test.ts` 对 dock 接线的相邻空行断言。本单没有改这三处源文件。
