# T023 D310 刀1：场地 CC0 PBR

基线：main `a88679a112671b64378a41bf0a899f9737cdb660`。Draft：https://github.com/lenaelelle672-beep/uniview-twin/pull/30 。不合入。

## 改了什么

四套 Poly Haven CC0 1k `nor_gl` + Rough，转 WebP quality 80，放在 `public/textures/ground/`。没有反照率，没有金属度，没有新 npm 依赖。

`src/scene/groundTextures.ts` 在 `window.__twinReady === true` 且 `window.__twinFirstFrameAt != null` 之后，再等到 `performance.now() - __twinFirstFrameAt >= FLOOR_SHELL_AFTER_FIRST_MS`（2600，与楼层壳同一道门；d126 的 cutoff 在首帧后约 64 ms，只多一帧会时进时出），然后才多一帧和一次 `requestIdleCallback`（超时 1200 ms），用 `TextureLoader` 把 `normalMap` 和 `roughnessMap` 赋给 `grassMaterial` / `roadMaterial` / `pavingMaterial` / `sidewalkMaterial`。`RepeatWrapping`，`colorSpace = NoColorSpace`，赋完 `needsUpdate`，并打一帧 `window.__twinInvalidate`。昼夜颜色仍只走 `applySurfaceMode`。

道路和人行道的 `PlaneGeometry` UV 原是 0–1。合并后印成世界 `(x, -z)`，和挤出顶面同一套米制。草地、铺装沿用挤出 UV。`repeat = 1 / 物理边长`。

性能档各向异性为 1，其余为 4。

## 首帧闸

`docs/T012-evidence/first-screen-t023.json` 是「首帧 + 1 rAF + idle」那一版的记录。`perf/2026-10-18.md` 在 tip `4f1a0b7` 上复测：均衡 hardGate 约 **2076207**（上限 436361），八张 `/textures/ground/*.webp` 都在 `hardGateFiles` 里，请求落在首帧后约 55–60 ms，仍在 d126 cutoff（首帧 + 64 ms）内。balancedFx **101397** 仍过。这一版把 TextureLoader 推迟到首帧后 2600 ms，尚未按同一套 perf lock 重测 hardGate。

## 已知问题

- 上面的 `first-screen-t023.json` 不能当作当前闸门结果。2600 ms 延迟还没有新的 hardGate 数字。
- 法线槽从无到有会重编译场地 shader，发生在首帧 2600 ms 之后。
- 总览机位很远，1k 法线会被 mip 平均，近处才看得清纹理。repeat 保持资产物理边长。
- `roughnessMap` 会乘上 `applySurfaceMode` 里的 roughness 标量。
