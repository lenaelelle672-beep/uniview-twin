# T024 D310 刀2：SoftShadows 仅非 perf

基线：main `4624f0b9bbfa3004f8f055e024c7f466cc512f08`（T023 已合）。Draft PR 见文末。不合入。

## 范围

balanced / high（`quality !== 'perf'`）挂 drei `<SoftShadows>`。perf 保持现有阴影。samples 5（落在 4–6）。size 25、focus 0，沿用 drei 社区默认。0 新依赖。不改场地贴图，不开 Bloom。

## 改了什么

- `src/components/scene/BalancedSoftShadows.tsx`：从 `@react-three/drei/core/softShadows` 挂 `<SoftShadows samples={5} size={25} focus={0} />`。`Scene.tsx` 只在 `quality !== 'perf'` 时渲染这个组件。
- 挂载时机：等 `__twinFirstFrameAt` 落下，并且 `__twinFrames >= 1`（DemandLoop 至少完成一帧，总览上这一帧带走 D286 的立即烘）。单层还要 `isCameraRested()` 且 `shadowBakePending() === false`。门打开后再让出一帧才挂上，避免和烘影 / 飞入同帧。没有贴图请求，不读 `FLOOR_SHELL_AFTER_FIRST_MS`，T023 场地懒加载原样。
- 卸载：drei 10.7.9 会把 `shadowMap.type` 从 `BasicShadowMap` 写回挂载时抓到的值。组件在子清理之后再兜底：若仍是 `BasicShadowMap`，回到挂载前的类型；挂载前已经是 Basic 时回到 `PCFShadowMap`（percentage，three 0.186 的值是 1）。
- `useBalancedWarmup` 在 PCSS 挂着时不再把 `shadowMap.type` 写回 PCF，避免和 raw depth 采样器打架。挂上之后下一帧、且当时没有飞入烘影，才打一次 `needsUpdate`。
- 现成库：`@react-three/drei` 10.7.9 的 `SoftShadows`。没有新 npm 包。

## 已知问题

- drei 的 `reset()` 会遍历场景 `dispose` 材质并 `gl.compile`。挂载和卸载各一次整场景重编译。已经避开首帧后的 D286 当帧和单层飞入，重编译本身仍会卡一下。SwiftShader 上这次挂载落在首帧之后约 2–5 秒（主线程编译会挡住 rAF），不是同一帧。
- 挂载期间 `shadowMap.type` 是 `BasicShadowMap`（0）。这是 drei 为 PCSS 取 raw depth 的行为。
- 本机 headless SwiftShader（`?q=balanced` 钉住画质，避免软件渲染自动降到 perf）冒烟：挂上后 `window.__twinSoftShadows.samples === 5`，`shadowMap.type === 0`，console 0。切到 perf 后戳被清掉，`type` 回到 `PCFShadowMap`（1），阴影关闭。冷启动 `?q=perf` 不挂 SoftShadows。夜景仍挂着，type 仍是 0，console 0。没有新的首屏贴图请求。既有 troika 字体 CDN 请求还在，不是本单引入的。
- hardGate / balancedFx 没有按 perf lock 重出数字。静态引入 `softShadows`，无新贴图，网络体积相对 `4624f0b` 预期接近 0。
- 夜景 Bloom 不在本单。软影边缘没有做像素级对比。
