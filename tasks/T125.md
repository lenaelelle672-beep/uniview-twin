# T125：设备到告警的静态贝塞尔关系弧（C1）

基线 `a7ee0306a0b4262a4a1dd1a92f343ee27cb8cb1f`（短 `a7ee030`）。独立 draft PR。不合入。

## 验收

- 单层里用 drei `CubicBezierLine` / `QuadraticBezierLine` 把告警电脑连到它的告警圆标。默认关。`?relationArc=1` 或 `window.__twinSetRelationArcs(true)` 才打开。
- 最多 4 条。偶数条二次，奇数条三次。线宽 1.5，分段 12。控制点在 `useMemo` 里由一份圆标矩阵快照生成一次。没有 `useFrame`，不逐帧改点列。
- 只连当前层、有工位号、状态为告警、圆标字形也是告警、并且有对应告警记录的电脑。圆标个数和电脑工位个数不一致时一条都不画。落点用已经摆好的 `DeviceBadges` 世界矩阵，不读数据里的桌面 x/z。
- 总览、蓝图、楼栋爆炸、工位爆炸时卸下。不跟着动画改点。
- 和导览轨、测距、走道、房间标签、批辅线分开。不拿来当装饰线。
- 0 新 npm。不升 drei 10.7.9 / R3F 9.8.1 / three 0.186.1 / `@react-three/postprocessing` 3.1.3 / postprocessing 6.39.5。

## 改了什么

`src/relation-arcs/plan.ts` 配对和冻住控制点。`RelationArcs.tsx` 才深路径引用 drei 的两条曲线。`mount.ts` 只做门闩，不引用 drei / three。

生产构建走 `relation-arc-after-hash`。哈希定稿前从 dock 摘掉这条接线，定稿后另出 `RelationArcMount.js`。开关打开并且人在单层休息姿态时，挂载包再加载 `RelationArcs.js`，曲线包再加载 `CubicBezierLine.js`、`QuadraticBezierLine.js`、`Line.js`。入口包没有导出曲线类时，另出 `BezierCurve3.js`，里面的 `Vector3` 仍是入口包那一个，和 `Line.js` 的 `instanceof` 对得上。

格网叠层把关系弧放在第 17 个槽，缺省是空。`composeOverlay.length` 仍是 3。

## 已知问题

- 地址栏同步会丢掉 `relationArc`。开关看启动时的导航地址，所以第一次带这个参数进来仍然开着。刷新成丢掉参数之后的地址会回到关。
- 线宽 1.5、拱高大约 0.23 米。默认单层取景里它是圆标旁边的短笔画。拉近才看得出弯。
- drei 的 `LineProps.segments` 是布尔，曲线的 `segments` 是分段数，交叉后类型是 `never`。运行时用对象展开把数字传进去。
- 楼栋爆炸和工位爆炸会卸下弧，不跟着壳的动画走。
- 与本单无关的既有失败：`explodeFitGate.test.ts` 不允许 `FloorStageCamera` 出现 `frameloop`；`rectArea.test.ts`、`fileSave.test.ts` 对 dock 接线的相邻空行断言。本单没有改这三处断言所看的源位置。
