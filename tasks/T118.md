# T118：drei OrthographicCamera 单层平面图俯视（C5）

基线 `596cbef4473c6a114815ce574ae6ba3f42156bea`（合口证 tip `596cbef`，#118 已合）。旧 tip `f3ed50c` 与旧 parent `13c22ab` 作废。独立 draft PR #122。不合入。不测 merge `0a09a8d`。

## 验收

- 单层会话里用 drei `OrthographicCamera`（`@react-three/drei/core/OrthographicCamera`）做「平面图」俯视。默认关。`?floorPlan=1` 只在这次会话打开，不写回地址栏。按钮在视角书签那一行，快捷键 P。`window.__twinSetFloorPlan(boolean)`。
- 挂上时 `makeDefault` 把 R3F 默认相机换成正交相机。北（-Z）朝屏幕上方。楼板 `FloorPlate` 的盒子在本地算，不调用 `setLookAt` / `fitToBox` / `dollyTo`。
- 卸下时 drei 把原来的透视相机还回去。同一层退出后透视仍停在进平面图之前的那一镜；中途换了层，`FloorStageCamera` 的 `framedKey` 对不上，会重新取景。
- CameraControls 始终拿着最初那台透视相机，不跟着默认相机换。俯视期间只 `stop()` 并关掉拖曳（`enabled = false`），不换 `update` / `setLookAt`。沿轨已经占着镜头时不动它。
- `FloorStageCamera` 看到 `window.__twinFloorPlan.held` 就不再用正交相机的位置判断飞到没到，也不去 fit，工位爆炸取景同样让开。
- 总览、蓝图、首帧之前不挂，所以它不是首屏相机。导览、沿轨、工位爆炸占着镜头时卸下正交相机，会话开关还留着。楼栋爆炸只在总览改位移，单层里不因此让路。
- 0 新 npm。不升 drei 10.7.9 / three 0.186.1 / `@react-three/postprocessing` 3.1.3。
- `balancedFx` 里拷贝用的 `new OrthographicCamera(-1, 1, 1, -1, 0, 1)` 和接触阴影那台正交相机都不改。不改 Canvas 的透视相机参数，不改 `grid/mount.ts`。

## 改了什么

`src/floor-plan/`：`plan.ts` 管门闩和取景，`hold.ts` 只管拖曳暂停，`marks.ts` 把首帧锁住并把被清掉的就绪标记写回去，`mount.ts` 做会话和按钮，`FloorPlanCamera.tsx` 才引用 drei。

dock 在首帧之后才 import。接线放在 T116 屏幕标注之后、T115 拾取代理仍在更前。生产构建用 `floor-plan-after-hash`：哈希定稿前把 dock 里的接线摘掉，定稿后另出 `FloorPlanMount.js` / `FloorPlanCamera.js`，react / fiber / three / store 都从已经哈希的入口包复用。`FloorPlanCamera.js` 要等会话打开并且人已经在单层里才请求。拾取代理走格网槽，平面图走测距槽，两套开关互不替换。

平面图挂上之后，空闲门会换掉 `invalidate`。下一次昼夜提交让 RenderProbe 的 effect 重跑，清掉 `__twinReady`、首帧和树 lo。树不会因为这次清理再画。会话开着或关着都一样：订阅到场景修订（含昼夜）之后晚一拍看标记，丢了就写回挂上之前记住的值。200ms 再看一次。不改 RenderProbe。

drei 这份组件会顺带分配一张 256² 的离屏目标。不把 children 写成函数，它就不会往那张目标上多画一次。

换默认相机会让 RenderProbe 按相机依赖重跑，清掉 `__twinReady`、首帧和树 lo 标记。正交相机如果跟着退回 `off-first-frame`，会刚换上就被卸掉。首帧出现过一次就锁住。换相机之前记住那些标记，清掉之后写回去。不改 RenderProbe，避免为这件事再动 hardGate。

## 已知问题

- 正交相机挂着的时候，drei 会留着一张 256² HalfFloat 离屏目标。卸下后跟着组件释放。没有函数 children，不会每帧多画一次。
- RenderProbe 仍会在默认相机对象换掉、或 `invalidate` 身份换掉之后的下一次场景提交里清一次就绪标记。平面图在下一拍把换之前的值写回去。不改探针本身。平面图还没挂上时，这次清理跟本单无关。
- SwiftShader 上进层 Suspense 可能把探针卸下几秒。首帧标记只要出现过一次，平面图就不会因此退回透视。
- 与本单无关的既有失败：`src/scene/stage/explodeFitGate.test.ts` 不允许 `FloorStageCamera` 出现 `frameloop`，文件里原有注释「不把 frameloop 改成 always」。T111 已记录，本单不改那条断言。
